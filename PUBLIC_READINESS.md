# Public-use readiness and feature roadmap

Reviewed on 7 September 2026. This is a source review of the existing backend and deployment files, not a penetration test or production certification. Backend fixes below are recommendations; the accompanying UI work does not resolve them.

The main launch priorities are durable link storage, owner-only management, reliable expiry, and production configuration. Shortening, custom aliases, expiration, redirects, stats, and aggregate analytics already have backend implementations.

## Fix before a public launch

| Priority | Finding and evidence | Recommended change | Acceptance criteria |

Object-level ownership checks follow [OWASP API authorization guidance](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/). Redis documents [persistence options](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/) and [counter/rate-limiter patterns](https://redis.io/docs/latest/commands/incr/); persistence must cover the actual source of truth. Spring Boot documents [external configuration](https://docs.spring.io/spring-boot/reference/features/external-config.html) and [health endpoints](https://docs.spring.io/spring-boot/reference/actuator/endpoints.html).

## Operational and maintenance improvements

- Choose `backend/` as the backend source of truth: Compose builds it, while a second root `src/` and `pom.xml` have drifted. The root Dockerfile contains `COPY scr` and `RUN nvm` (`src/Dockerfile:7`, `:9`), and the root service lacks the creation timestamp fix already present in `backend/`. Consolidate deliberately after checking how local builds are used.
- Fix the cleanup conversion: `backend/src/main/java/com/codebreaker/shortlink/config/CleanupScheduler.java:22` uses `minutes * 60 * 100`, so the configured 30-minute interval runs every 3 minutes. Use a duration property or the correct unit conversion. Cleanup only marks links inactive; it does not bound map growth or event retention.
- Bound analytics retention and aggregation costs. Every click is kept indefinitely, and every analytics request traverses the history. Referrer URLs can include sensitive query parameters, so store only the information actually needed for the dashboard.
- Reduce production DEBUG logging and avoid logging full destination URLs with potentially sensitive query strings (`backend/src/main/resources/application.yaml:34`, `services/UrlShortnerServices.java:86`). Add request IDs, redirect latency/error metrics, backup monitoring, and alerts for unexpected failures.
- Add a CI workflow for frontend build/tests and backend tests. Current backend tests cover creation timestamps; add meaningful integration coverage for owner authorization, duplicate aliases, concurrent traffic, expiry with a warm cache, restarts, and Redis outages. The Docker build currently skips tests.
- Add a clear missing/expired/disabled-link page, a privacy explanation, and a visible abuse-report action. A public shortener also needs a way to review reports and disable malicious destinations without affecting unrelated links.

## Feature roadmap

| Order | Feature | User value | Dependency |
| --- | --- | --- | --- |
| First | Copy/share feedback, live destination/alias preview, expiry presets, mobile layout, keyboard-friendly forms, and useful loading/error states | Makes the core create-and-share flow faster and easier to understand. | Existing shorten API; mirror validation on the server. |
| Included in this UI update | Recent links with search/sort, individual removal, and CSV export; history stays in the current page session by default, with an explicit option to remember it in this browser | Lets a guest find or export links created earlier without retyping a code. | Optional browser storage is device-only; this is not ownership or durable server storage. Removing an item only removes it from local history. |
| First | Real click charts with refresh status and accessible text values | Gives the existing `/api/analytics/{code}` data a useful UI. | Aggregate API data; private owner authorization before public rollout. |
| Next | Downloadable QR codes generated locally | Makes links useful on posters, menus, presentations, and printed materials. | Generate a standards-compliant QR from the short URL and verify scanning; avoid sending destinations to an unrelated third-party QR service. |
| Next | Account dashboard with folders/tags, pagination, search, and owner-only edit/pause/delete | Turns the shortener into a dependable personal link library across devices. | Authentication, durable storage, ownership checks, and new list/update endpoints. |
| Next | UTM campaign builder and owner-authorized analytics export | Helps users compare shared campaigns without manually assembling query strings. Local recent-link CSV export is already included in this UI update. | Safe URL construction; analytics exports require owner authorization. |
| Later | Verified custom domains, team roles, scoped API keys, and bulk creation | Serves teams and repeated business workflows. | Domain verification, quotas, audit records, scoped authorization, and the launch fixes above. |

Recommended sequence: finish the launch fixes, validate a small public beta with the polished core UI, then add QR downloads and the authenticated dashboard. Custom aliases and expiration already exist; improve their reliability and usability before adding more options.
